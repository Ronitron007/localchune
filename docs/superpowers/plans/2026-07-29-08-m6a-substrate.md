# M6a — org-layer substrate (likes, plays, crates)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Likes with anonymous counts, event-based play counts, crates with a
public toggle and manual ordering — schema, RPCs, routes, and server-rendered
UI. First of three M6 slices (spec:
[`2026-07-29-m6-org-layer-design.md`](../specs/2026-07-29-m6-org-layer-design.md)).

**Architecture:** Two migrations (19: likes + plays + pool-view growth;
20: crates). All mutations go through `security definer` RPCs behind thin
Astro API routes. UI is server-rendered with form fallbacks; JS enhances
(optimistic like, drag reorder) but is never required.

**Tech stack:** Astro SSR on Cloudflare, Supabase Postgres + pgTAP, vanilla
site-script JS, vitest (node env).

**Branch:** `rohan/m6a-substrate`.

## Global constraints

All of CLAUDE.md applies. Binding highlights:

- Brutalist idiom: server-rendered pages, forms as no-JS fallback, no new
  islands. JSON `{error}` failures on API routes.
- **Revoke-first grants** on every new table (hosted ACL default — see
  CLAUDE.md §Hosted Supabase) + pgTAP `throws_ok` with errcode `42501`,
  4-arg form, one `plan()` per test file.

  numbering shifts again** (same note as the pool-ux batch): every table

- [ ] **Step 3: write migration 19.** Core content:

```sql
create table public.likes (
  file_id    uuid not null references public.files(id) on delete cascade,
  user_id    uuid not null references public.members(user_id) on delete cascade,
  created_at timestamptz not null default now(),   -- "liked this week" (M6c)
  primary key (file_id, user_id)
);
alter table public.likes enable row level security;
revoke all on public.likes from public, anon, authenticated;
grant select, insert, update, delete on public.likes to service_role;

create table public.play_events (
  id        bigserial primary key,
  file_id   uuid not null references public.files(id) on delete cascade,
  user_id   uuid not null references public.members(user_id),
  played_at timestamptz not null default now()
);
alter table public.play_events enable row level security;
revoke all on public.play_events from public, anon, authenticated;
grant select, insert, update, delete on public.play_events to service_role;
create index play_events_file_idx on public.play_events (file_id);
create index play_events_window_idx on public.play_events (played_at);
```

`toggle_like` follows `bump_download`'s exact gate shape (active-member
check, `pool_visible_states()` check raising P0002), then:

```sql
  delete from public.likes where file_id = p_file and user_id = auth.uid();
  if not found then
    insert into public.likes (file_id, user_id) values (p_file, auth.uid());
    v_liked := true;
  else
    v_liked := false;
  end if;
  select count(*) into v_count from public.likes where file_id = p_file;
  return query select v_count, v_liked;
```

Delete-first makes a retried single call safe and needs no `on conflict`.
`bump_play` = same gates, then one INSERT into `play_events`. A counter
would be wrong here — M6c's "hot this week" needs the timestamps.

View growth (append-only, after the 15b Task-4 block):

```sql
  coalesce(lk.like_count, 0)::int            as like_count,
  exists (select 1 from public.likes l
           where l.file_id = f.id and l.user_id = auth.uid())
                                             as liked_by_me,
  coalesce(pe.play_count, 0)::int            as play_count,
  ((lpad((999999999999::bigint - coalesce(lk.like_count, 0))::text, 12, '0')
   ) collate "C")                            as sk_likes,
  ((lpad((999999999999::bigint - coalesce(pe.play_count, 0))::text, 12, '0')
   ) collate "C")                            as sk_plays
```

with two new LEFT JOIN LATERAL (or grouped-subquery) sources — **not plain
joins** (the claim-multiplication hazard 15b documents). `liked_by_me` is a
correlated EXISTS on `auth.uid()`, which resolves fine inside the definer
RPC. `pool_list`/`pool_get`: DROP + recreate, return-table extended with the
five columns, sort arms `'likes_desc' -> sk_likes`, `'plays_desc' ->
sk_plays` following the `sk_downloads` arm exactly (composite cursor with
`sk_added` tiebreak — copy the existing arm's shape, do not invent).

                left join public.crate_items ci
