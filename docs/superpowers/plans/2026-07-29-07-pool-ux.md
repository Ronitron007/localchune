### Task 1: Folder upload — recursive traversal

**Files:** create `src/lib/dir-walk.ts` + `src/lib/dir-walk.test.ts`; modify
the dropzone component (`src/components/UploadDropzone.tsx`) and
`src/pages/upload.astro` (add a "select folder" input).

Mechanics:
- Drop path: `DataTransferItem.webkitGetAsEntry()` → recursive walk of
  directory entries. **The classic bug is `createReader().readEntries()`
  returning at most ~100 entries per call — it MUST be called in a loop
  until it yields an empty batch.** A unit test with a fake reader yielding
  100+100+3 entries is mandatory.
- Picker path: a second `<input type="file" webkitdirectory>` alongside the
  existing file input (folder pickers cannot mix with file pickers in one
  input).
- Filter: accept only extensions the upload policy already allowlists —
  import from `src/lib/upload-policy.ts`, do not duplicate the list. Skip
  dotfiles, `__MACOSX`, zero-byte files. Depth cap 12; file-count guard at
  2,000 with a clear message (the policy's own batch ceiling governs).
- Output: a flat `File[]` fed into the EXISTING pump/journal pipeline
  untouched — the walker only discovers files; dedupe of already-journaled
  files is already the journal's job.
- Walker is pure-testable in node with faked entry objects; the browser drop
  path is a manual check.

**Files:** modify `src/layouts/Shell.astro` (the persisted
`<audio id="player-audio" controls>` bar) + the player script + css.

  Keep the `<audio>` element (no `controls` attr) as the engine; the

- Works at 375px width without overflow. Manual checks: iOS Safari + Android
  Chrome (owner's phone) — desktop behaviour unchanged.

### Task 4: Download + upload counts (format-agnostic-ready)

**Files:** migration `…_15_track_stats.sql`; modify
`src/pages/api/track/[id]/download.ts`; surface in `pool_tracks`
view/`pool_list` + detail page; pgTAP.

- `track_stats(file_id uuid pk references files on delete cascade,
  download_count bigint not null default 0)`. Definer fn
  `bump_download(p_file uuid)` — upsert increment; grant execute to
  authenticated (any member's download counts); revoke-first; the download
  route calls it fire-and-forget AFTER minting the signed URL (a stats
  failure must never block a download).
- **Upload count is not a new counter** — it is `count(*) from file_claims`
  per file, the mechanism M2 built for exactly this. Expose it in the view.
- Format-agnostic by design, not yet by data: counts key on `file_id` today
  because the canonical track identity does not exist until M4. **CARRY TO
  M4 (must appear in its plan PR): the merge operation folds
  `download_count` (sum) and claims onto the surviving identity, inside the
  same reversible merge event.** This is the owner's stated intent — counts
  belong to the track, not the encode.
- Detail page shows both counts; pool table shows downloads.

### Task 5: Uploader tags — added 2026-07-29, owner request

Verbatim intent: "give the uploader an ability to add tags… at any point of
time for all the tracks that he's uploaded."

**Files:** migration `…_16_file_tags.sql`; tag editor on the track detail
page (uploader-only affordance); tag chips on detail + pool rows; `pool_list`
search extended to match tags; pgTAP.

- `file_tags(file_id uuid references files on delete cascade, tag_display
  text not null, tag_key text not null, created_by uuid not null, created_at
  timestamptz not null default now(), primary key (file_id, tag_key))`.
  `tag_key` = trimmed, casefolded, whitespace-collapsed form of
  `tag_display` — dedupes "Deep House" vs "deep house" while preserving the
  uploader's casing for display. Cap: 32 chars/tag, 20 tags/file, enforced
  in the definer functions with clear errors.
- `tag_add(p_file, p_tag)` / `tag_remove(p_file, p_tag_key)` — `security
  definer`, **ownership checked in-body** (`files.uploaded_by = auth.uid()`),
  editable at ANY time (no state restriction beyond the file existing),
  revoke-first grants, 4-arg `throws_ok` pgTAP for the non-owner case.
- Visibility: any member sees tags wherever they see the track (pool rows as
  small chips after the title, full list on detail). Only the uploader gets
  the editor (server-rendered form posting to an API route, brutalist idiom
  — no island; a plain POST form with redirect-back matches the shell).
- Search: `pool_list`'s `q` predicate extends to `exists (select 1 from
  file_tags t where t.file_id = f.id and t.tag_key like …)` — one filter box
  searches title, artist, filename AND tags.
- **CARRY TO M4:** merge unions tags onto the surviving identity (same
  event-recorded, reversible treatment as counts and claims).
- **CARRY TO M8:** these are exactly the `source='user_tag'` tier of the
  genre design (PRD §9.1) — the normalisation pipeline consumes `tag_key`
  through the synonym table. Do not pre-normalise into the controlled
  vocabulary now; that is M8's job.

Order update: 1 → 2 → 4 → 5 → 3.

### Task 7: Usernames — added 2026-07-29, owner request

Verbatim: "every time a new user signs up, they get to select their username…
we use this username… pick a standard way… make sure you have added
validations."

**The standard (decided):** `^[a-z][a-z0-9_]{2,19}$` — 3–20 chars, lowercase
letters/digits/underscore, must start with a letter. Input is lowercased
before validation (users may type caps; storage is canonical lowercase, so
uniqueness is case-insensitive by construction). Reserved list (~20: admin,
owner, root, system, localchune, pool, track, upload, api, auth, login, me,
all, everyone, anonymous, deleted, support, staff, mod, null). Set once at
claim; changing later is out of scope v1.

- Migration `…_17_usernames.sql`: `members.username text unique` (nullable —
  existing members claim on next visit); `username_set(p_username)` definer
  fn — lowercases, validates format + reserved + uniqueness **in-body** with
  clear distinct errors, refuses a second set, revoke-first, execute to
  authenticated.
- `/welcome` claim page (brutalist, plain POST form → api route →
  `username_set`, redirect on success, inline error re-render on failure).
- Middleware: a member with null username hitting any page outside
  {/welcome, its api route, /auth/*, /login} redirects to /welcome — the
  "at signup" guarantee, and it retrofits existing members incl. the owner.
- Display: `pool_tracks` uploader column becomes
  `coalesce(m.username, split_part(m.email,'@',1))` (new small migration
  replacing the view; DROP+CREATE rules apply if function column sets
  change); AppNav greets by username; /admin table gains a username column
  (keeps email — it is the allowlist key).
- pgTAP: format rejections (short/long/leading-digit/space/hyphen), reserved
  rejection, duplicate → clear error not raw 23505, set-once enforced,
  uppercase input canonicalised, anon refused.

Order update: … → 3+6 together (both live in Shell/css) → 7 → batch review →
deploy.
