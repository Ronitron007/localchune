# Milestone 4 — Dedup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two uploads of the same recording become one `track_id`, reversibly. A member uploads a file; the analysis pipeline fingerprints it; the matcher retrieves candidates, scores them, and either assigns the existing track (≥0.90), files a review row (0.70–0.90), records a near-miss (0.40–0.70) or mints a new track (<0.40). Every automatic merge is an event carrying its own undo payload. Every uploader keeps their contribution credit whether or not their bytes survive.

**Spec:** [`docs/PRD.md`](../../PRD.md) §6 (the whole section), §3 (`tracks` / `files` / `file_claims`), §7.2 (the quality forensics that decide keep-if-better), §10 (contributed vs occupying). UI: [`specs/2026-07-28-ui-components.md`](../specs/2026-07-28-ui-components.md) §8, rendered in the idiom of [`specs/2026-07-29-ui-brutalist-design.md`](../specs/2026-07-29-ui-brutalist-design.md).

**Architecture:** Retrieval and every write live in Postgres behind `security definer` RPCs. The bit-error scoring is a pure TypeScript module called from the analysis queue consumer, which is the only process that already holds both a fresh fingerprint and the `service_role` key. The review UI is server-rendered `.astro` with GET filters and POST forms — no islands, matching M5.

**Tech stack:** unchanged — Astro 7 SSR on `@astrojs/cloudflare`, Supabase (Postgres 15), Cloudflare Queues + Containers, Vitest (node), pgTAP, pytest.

### Four gaps this plan has to close before it can do its own job

1. **Forensics is NULL end to end, so `is_upgrade` cannot run.** `main.py` calls `forensics.measure_cutoff()` and *logs* the result, then deliberately returns `forensics=None`, because `classify_ancestor()` needs an `hf_ref_delta_db` that nothing computes and `Forensics` needs a **measured** effective bit depth and sample rate that nothing computes. PRD §7.2's keep-if-better rule is the judge of which file survives a merge, and it is built entirely on those numbers. **Task 1 is therefore the forensics producers, and it is first.** The alternative — synthesising a tier from ffprobe's *declared* bit depth — is precisely the lie the forensics pass exists to catch.

2. **`files.content_sha256` is NULL on every row, so PRD §6 layer 0 is not computable.** The PRD calls layer 0 "free (already computed)". It is not: `AnalyzeResponse` has no such field and `analysis_persist()` never writes the column. Task 1 adds a `hashlib` pass over the file the container already has on disk (~0.1 s for 40 MB), and Task 2 replaces `analysis_persist()` to store it.

3. **There is no `public.tracks` table.** Every `files.track_id` is NULL. Task 2 creates the table, adds the foreign key, and backfills one track per already-stored file — without that backfill the first real merge has nothing to merge *into*.

4. **The PRD's GIN opclass does not apply to the shipped column.** PRD §6 writes `using gin (query_items gin__int_ops)`. `gin__int_ops` comes from the `intarray` extension and accepts `int4[]` only; the shipped column is `bigint[]`. Task 4 uses the built-in `array_ops`, which supports `&&` on any array type. (The masked items are all `< 2^20` and would in fact fit `int4` — the `bigint[]` choice was made for the *raw* fingerprint values, which do exceed `2^31`. Adding a shadow `int4[]` column to reach `intarray` would be a second copy of the same data to win a constant factor on a table of 2,000 rows. PRD §6 explicitly forbids that class of optimisation: *"Do not build pgvector, HNSW, LSH, a separate inverted-index table, or partitioning."*)

## Global Constraints

Each is a bug already paid for once. Violating one reintroduces it. The first six are load-bearing for every SQL task in this plan.

- **Revoke first, then grant.** A hosted Supabase project ships an `ALTER DEFAULT PRIVILEGES` granting `anon`, `authenticated` and `service_role` `arwdDxtm` on every new table in `public`; `supabase start` locally does not. A bare `grant select` is therefore a **no-op against production** and the real ACL there is "everything". Every new table in this milestone does `revoke all on <t> from anon, authenticated;` before its grant, and pgTAP asserts a `42501` on a write attempt. Verified 2026-07-29 by diffing `pg_class.relacl` on both databases; migrations 09 and 10 carry the same note.
- **Exactly one `plan()` per pgTAP file**, and `throws_ok` in its **4-argument** form (`throws_ok($$sql$$, 'errcode', 'message', 'description')`). A 2-argument call silently matches on the wrong thing.
- **pgTAP fixture order: `public.allowlist` BEFORE `auth.users`.** The `handle_new_user` trigger aborts otherwise, and it provisions `public.members` itself — never insert a `members` row by hand; `update` it to set `access_expires_at`.
- **Every mutation is a `security definer` function** with `set search_path = ''`, an explicit ownership or membership check in its body, `revoke execute ... from public, anon` and a single deliberate `grant execute`. Postgres grants `EXECUTE` to `PUBLIC` by default on every new function, so the revoke is not optional. A helper reachable only from another definer function is granted to **nobody** — the pattern `ingest_set_state()` (migration 07) and `pool_tracks` (migration 11) already use.
- **No RLS policy on table X may `SELECT FROM` table X** — 42P17 at runtime. Reference `public.files` and let its own RLS do the work, exactly as `audio_analysis`'s policy does.
- **`state_changed_at`, never `created_at`,** for any "how long has this been stuck" predicate. `created_at` is when the row was minted, before the bytes moved.
- **Migrations are never edited after being applied** to the hosted project. Migrations 00–14 are applied. M4 lands as **15, 16, 17**. Changing a shipped function means a new `create or replace` in a new file.
- **In a plpgsql `returns table`, output columns are variables.** A bare `bpm` is ambiguous against `pool_tracks.bpm` and raises **42702 at runtime, not at create time**. Table-qualify every reference inside every function body. Migration 08 hit this; migration 12 documents it.
- **`on conflict (file_id)`, never `on conflict (file_id, analysis_version)`** on `audio_analysis` — `file_id` is the primary key and there is no second unique index to match, so the pair raises 42P10.
- **RPC numeric parameters are `int` / `double precision`, never `smallint` / `real`.** PostgREST hands over JSON numbers and `int4 → int2` is an assignment cast, so a `smallint` parameter makes function resolution fail outright.
- **`collate "C"` on any text used in a keyset cursor or in a `CASE` that mixes sort keys** — differing implicit collations raise 42P22 at runtime.
- **Container changes carry a rollout gotcha.** `rollout_step_percentage` defaults to `[10,100]`: after `wrangler deploy` reports SUCCESS, requests still hit the **old** image for several minutes while `containers list` says "provisioning". Poll for `ready` or pass `--containers-rollout=immediate`. `wrangler secret put` also needs ~30 s to propagate. Task 1 changes the image, so this applies to Task 1 and to the Task 8 acceptance run.
- **Vitest runs in the node environment. No jsdom.** Pure logic is unit-tested. Real playback, real audio elements and real R2 round trips are manual checks in Task 8's checklist, never a stubbed-green test.
- **MIT header on every hand-authored file**, plus the AGPL note. Copy the three-line block from `src/lib/email.ts`. `.astro` files carry it inside the frontmatter fence, `.sql` uses `--`, `.py` uses `#`.
- **`Astro.locals.supabase` is the request's client.** Never construct a second one — it re-reads the original `Cookie` header and misses a rotation the middleware just performed.
- **Degraded analysis is data, not an error.** `bpm = 0`, `forensics = null` and `lossy_ancestor = 'abstain'` are all legal results that must be stored and rendered as themselves.
- **`RECONCILE_DELETE_PENDING` stays `"false"`.** M3's carry: a `failed` row can now hold perfectly good bytes whose *analysis* failed, and `reconcile.ts`'s `STATES_SAFE_TO_AUTO_DELETE` cannot yet tell the two apart. M4 adds `rejected_redundant`, which is a third meaning again. Task 5 deletes a reclaimed object inline through the analysis Worker's own `AUDIO` binding rather than widening that list.

## Decisions

Each of these closes off an obvious-looking alternative. They were settled before the tasks were written.

### The matcher runs in the analysis queue consumer, with an hourly cron as its guarantee

Four candidate homes; three lose.

- **Inside the container.** It has the audio and it computes the fingerprint — but it holds *no credential of any kind*, by design (PRD §12: the Durable Object in front of it holds the only R2 binding, and the container never sees a Supabase key). It cannot run the candidate query. Ruled out on architecture, not on cost.
- **Inside Postgres.** The offset sweep is roughly 11.6 M 32-bit XOR-and-popcount operations per file. In plpgsql that is minutes. In C it is an extension, and hosted Supabase will not install one. Ruled out.
- **A standalone cron, decoupled from ingest.** It adds up to an hour of latency between "uploaded" and "deduped", puts a second reader of `fingerprints` in a second Worker, and — the real objection — has no advantage. PRD §6's concurrency protocol is *read → compute → re-verify under lock → write*, which is a caller holding a scored result across two round trips. A cron can do that. So can the consumer, and the consumer is already there.
- **The analysis queue consumer, immediately after `analysis_persist()` returns.** ✅ It already holds the `service_role` key, it already has the fresh fingerprint in memory, it already has an `AUDIO` R2 binding for reclaiming a redundant object, and Queues' at-least-once delivery is a retry mechanism already paid for. Scoring costs about 25 candidates × 2,886 frames × 161 offsets ≈ 11.6 M popcounts and about 300 KB of working memory — well inside a Worker's budget.

**The consumer's dedup step is best-effort, and that is deliberate.** `handleMessage()` acks once `persist()` succeeds. If dedup then throws and we `retry()`, the redelivery calls `analysis_begin()`, receives `'stored'`, and acks with *"not claimable"* — so the dedup would never run. Retrying the whole message instead would burn another ~45 vCPU-s of container time to recompute a fingerprint we already hold. So the consumer logs the dedup failure and acks.

That makes the backstop load-bearing rather than decorative. The maintenance Worker gains a fourth cron, `47 * * * *`, calling `dedup_pending()` — files that are `stored`, carry a fingerprint at the current `algo_version`, and have no `track_id` — and runs the same matcher over them. One matcher module, two callers. **A dedup failure costs an hour of latency, never a lost assignment.**

### `tracks` is created with identity and merge columns only

PRD §4 draws `tracks` with about twenty canonical-metadata columns (`artist`, `label`, `isrc`, `mbid`, `artwork_url`, `beat_grid`, …). Those are **M7's** output, and M5 already renders artist and title from `raw_tags` through `display_artist()` / `display_title()`. Twenty always-NULL columns is a placeholder that invites someone to read one. M4 creates `id`, `preferred_file_id`, `merged_into_track_id`, `merged_at`, `created_at` and nothing else. M7 adds its own columns in its own migration.

### A "not a duplicate" verdict is recorded against the **file pair**, not the track pair

`NotDuplicateAction` must make a pair never resurface. Recording it as `(probe_file_id, candidate_track_id)` is wrong, because track identity is exactly the thing merges and undos move around: a negative recorded against a track id survives a merge and then suppresses the wrong comparison. Files are immutable. `dedup_negatives` is keyed on `(file_lo, file_hi)` with `file_lo < file_hi` enforced by a CHECK, so the pair has one spelling and the primary key does the deduplication.

### The near-miss log is a **view**, not a fourth table

PRD §6 wants the 0.40–0.70 band retained so the vinyl-drift signature — near-misses clustering with a 1–3 % duration delta — can be spotted. PRD §15 names that cluster as the trigger for adding Panako. Every such pair is already a row in `match_decisions` with `band = 'related'`. `dedup_near_misses` is a view over that band which adds the duration delta as a percentage, the one derived number the trigger needs. A separate table would write the same facts twice.

### Thresholds are a row in a table, not constants in code

PRD §6 is unusually blunt: *"These numbers are AcoustID's constants adjusted by judgement, not evidence from your library."* If they live in SQL or TypeScript then calibrating them is a deploy, and every past decision becomes unexplainable. `dedup_config` holds one row per `algo_version` with the four thresholds, the GIN mask, and a `source` text saying where they came from. It ships seeded with the PRD's constants and `source = 'PRD §6 constants — NOT calibrated'`. Task 8 overwrites that row with measured values and a `source` naming the run. Each `match_decisions` row also copies the thresholds it used into its own `thresholds jsonb`, so a later recalibration cannot retroactively make an old decision unreadable.

### Merges are recorded as events; nothing is destructively rewritten

A merge is one `UPDATE tracks SET merged_into_track_id = winner`, plus whatever file re-pointing the keep-if-better rule decides, plus one `track_merges` row carrying the exact undo payload (`moved_file_ids`, `prior_track_id_by_file`, `prior_preferred_file_id`, `reclaimed_file_ids`). Crates (M6) will reference `track_id` and read through `canonical_track_id()`, so they are never rewritten by a merge and never rewritten by an undo. `undo_merge()` refuses when a later un-undone merge sits on top of either side, which forces newest-first unwinding.

**Every collapse goes through `merge_tracks()`, including an automatic one.** When a fresh upload lands in the `same` band it has no track yet, so the cheap thing is to point `files.track_id` straight at the winner — one `UPDATE`, no merge event. That is wrong. It would make automatic assignment the single collapse in the system with no undo payload and no row in the merges feed, which is exactly the case PRD §15 lists first (*"wrong auto-merges destroy someone's crates"*) and exactly what PRD §6's closing bullet warns about (*"nothing currently surfaces a completed auto-merge for after-the-fact review"*). So `dedup_resolve()` mints the probe its own track and immediately merges that track away. One collapse path, one undo, one feed, whether the matcher or a person decided.

> **Invariant, enforced by convention and not by the database** (PRD §4): the moment anything materialises a `track_id` into a denormalised table, a cached client payload or a playlist export, merge-undo silently stops being correct and nothing errors. Guard it in code review.

### The review UI is server-rendered `.astro` with GET filters and POST forms

The brutalist spec's rule is *"the pool is server-rendered, zero islands"*. A review queue is a list and a compare panel; there is nothing a browser must do. Filters and paging are `<form method="get">` and links. The three verdicts are `<form method="post">` posting to Astro endpoints that call one RPC and `303` back.

Those are **the first unsafe-method routes in the application.** M5's constraint — *"an unsafe-method fetch needs `content-type: application/json`"* — is about `fetch()` from an island. A native HTML form POST sends `application/x-www-form-urlencoded`, which is exactly the content type Astro's `security.checkOrigin` inspects, and a same-origin form carries a matching `Origin` header automatically. The form POSTs therefore get CSRF protection for free and need no header. This is written down because the next person to add a POST will otherwise copy the JSON convention into a place that does not need it.

A/B audition adds **no player code**. M5's shell already carries a persisted `<div transition:persist="player">` with a native `<audio controls>` and a ~30-line delegated click handler over `.play[data-track-id]`. The compare panel renders two of those links. The one addition is an optional `data-start` attribute, so a link can open at the point of maximum divergence — four lines inside the existing script, not a second player.

### The BER scorer is one module, in `src/lib/`, imported by both Workers

`src/lib/ber.ts` is pure: two `Uint32Array`s in, a score out. `workers/analysis/` (the primary caller) and `workers/maintenance/` (the cron backstop) both import it by relative path. This is the first cross-tree import in the repo and it is the right one — two copies of a bit-error scorer is exactly how two answers to "is this the same recording?" begin to disagree. `vitest.config.ts` already collects both `src/**/*.test.ts` and `workers/**/*.test.ts`, so one test file covers both callers.

### Metadata never decides

PRD §6 is explicit: the fingerprint decides, BPM and key only assist. They appear in this milestone in exactly two places — as display columns in the review UI, and as a **tie-break inside an already-qualifying candidate set** when more than 25 candidates clear the GIN and duration gates. No score, no band and no merge is ever a function of BPM or key. The "Feeling For You" pair reading 133.0 BPM / 11A on both copies is corroboration for the human reading the review row; it is not why they merge.

## The pipeline, end to end

```
analysis_persist() returns 'stored'
  │
  ├─ consumer calls dedup_candidates(file_id)          ← Postgres, ~2 ms
  │    layer 0a: files.content_sha256 exact match?     → done, no scoring
  │    layer 0b: fingerprints.fp_sha256 exact match?   → done, no scoring
  │    layer 1:  GIN query_items && probe_items
  │              AND algo_version = probe's
  │              AND |duration_s − probe| ≤ 10
  │              AND pair not in dedup_negatives
  │              order by shared items desc, limit 25
  │              (fallback: duration-only scan, cap 400)
  │
  ├─ consumer scores each candidate                     ← src/lib/ber.ts, ~300 ms
  │    offset sweep ±80 frames, score = 1 − BER
  │    emits best_offset_frames, overlap_frames, per_second_ber[]
  │
  └─ consumer calls dedup_resolve(probe, scored[])      ← Postgres, ~10 ms
       BEGIN
         pg_advisory_xact_lock(hashtext('localchune.track_assign'))
         SET LOCAL statement_timeout = '5s'
         re-run layer 0 + layer 1 INSIDE the lock       ← the whole point
         band the best score against dedup_config
         write match_decisions, then act on the band
       COMMIT
```

**Bands** (PRD §6, seeded values — Task 8 replaces them with measured ones):

| Band | Score = 1 − BER | Action |
|---|---|---|
| `same` | ≥ 0.90 | assign the existing `track_id`; run keep-if-better; insert the claim |
| `probable` | 0.70 – 0.90 | new `track_id`; a review row appears for a human |
| `related` | 0.40 – 0.70 | new `track_id` + a `track_relations` row (`version`); logged as a near-miss |
| `different` | < 0.40 | new `track_id`, nothing else |

**Keep-if-better**, once a probe lands in `same` (PRD §3 and §7.2):

| Situation | Files | Claim | `preferred_file_id` |
|---|---|---|---|
| Byte-identical (`content_sha256` hit) | probe row → `rejected_redundant`, object reclaimed | inserted on the **incumbent** file | unchanged |
| `is_upgrade(incumbent, probe)` is true | both kept, both `stored` | on the probe's own file | **moves to the probe** |
| Probe loses but differs in container or bandwidth | both kept, both `stored` | on the probe's own file | unchanged |
| Probe loses and is strictly dominated (same container, tier ≤, cutoff ≤ incumbent + 200 Hz) | probe row → `rejected_redundant`, object reclaimed | on the probe's own file | unchanged |
| Either side has NULL forensics | both kept | on the probe's own file | unchanged; decision noted `keep_both:no_forensics` |

A claim is written in every row of that table. That is PRD §10's rule: *"Contributed … counts every upload that resolved to a track, including ones whose file was discarded as redundant."* A redundant upload costs the uploader nothing and earns them the same credit.

`is_upgrade()` already exists, tested, in `worker/app/forensics.py` — but the merge decision happens in Postgres, so Task 4 ports it to SQL as `dedup_is_upgrade(jsonb, jsonb)` (migration 16) with the Python version's own test vectors replayed in pgTAP. Two implementations of one rule is a real cost; the alternative is a round trip to the container for a decision that needs no audio, which is worse.

- [ ] **Step 3: Implement the producers**

`measure_spectrum()` is an extraction, not a rewrite: `measure_cutoff()` already builds the max-hold spectrum and the 1–4 kHz reference. Splitting it means the FFT pass is paid **once** for cutoff, cliff and `hf_ref_delta_db` together, instead of twice.

```python
# worker/app/forensics.py — the new pieces. measure_cutoff() keeps its
# signature and its behaviour; its body becomes measure_spectrum() plus the
# threshold/cliff logic it already has.
from dataclasses import dataclass
import subprocess
import numpy as np


@dataclass(frozen=True)
class Spectrum:
    """One max-hold power spectrum in dB, plus its bin frequencies.

    MAX-HOLD across every window and every channel, never a mean: the
    encoder lowpass is a hard ceiling on the WHOLE file, and averaging drags
    the apparent cutoff down during quiet passages, manufacturing false
    positives. Channels are never downmixed -- MP3 intensity stereo folds HF
    into a shared channel and a downmix destroys that evidence.
    """
    db: np.ndarray
    freqs: np.ndarray
    ref_db: float
    windows: int


def measure_spectrum(windows: list[np.ndarray], sr: int) -> Spectrum | None:
    n_fft = 8192
    maxhold = None
    for w in windows:
        for ch in range(w.shape[1]):
            x = w[:, ch]
            for off in range(0, max(1, len(x) - n_fft), n_fft // 2):
                seg = x[off:off + n_fft]
                if len(seg) < n_fft:
                    break
                p = np.abs(np.fft.rfft(seg * np.hanning(n_fft))) ** 2
                maxhold = p if maxhold is None else np.maximum(maxhold, p)
    if maxhold is None:
        return None
    freqs = np.fft.rfftfreq(n_fft, 1 / sr)
    db = 10 * np.log10(maxhold + 1e-20)
    ref = float(db[(freqs >= 1000) & (freqs <= 4000)].mean())
    return Spectrum(db=db, freqs=freqs, ref_db=ref, windows=len(windows))


def hf_ref_delta_db(spec: Spectrum | None) -> float:
    """14-16 kHz energy relative to the 1-4 kHz reference.

    PRD 7.2's abstain gate: below -60 dB the track is dark or sparse and the
    detector has nothing to work with. Returning a fixed number here instead
    of measuring it is how a legitimately quiet master gets called a fake --
    which is the one error this module is tuned to avoid, because a false
    accept costs one wrongly-awarded credit and a false reject costs a
    contributor.
    """
    if spec is None:
        return -200.0
    hf = spec.db[(spec.freqs >= 14000) & (spec.freqs <= 16000)]
    if hf.size == 0:
        return -200.0
    return round(float(hf.mean() - spec.ref_db), 2)


# Standard rates, ascending. A file is demoted to the LOWEST rate whose
# Nyquist still comfortably contains the measured content.
_STANDARD_RATES = (22050, 32000, 44100, 48000, 88200, 96000, 176400, 192000)


def effective_sample_rate(declared_sr: int, cutoff_hz: int) -> int:
    """The rate this audio was really at, whatever the container claims.

    A 96 kHz FLAC brickwalled at 20.5 kHz is a 44.1 kHz master upsampled.
    Never returns MORE than the declared rate: the container cannot
    under-report, only over-report.
    """
    if declared_sr <= 0 or cutoff_hz <= 0:
        return max(declared_sr, 0)
    for rate in _STANDARD_RATES:
        if rate > declared_sr:
            break
        # 0.90 of Nyquist: a real 44.1 kHz master rolls off by ~20 kHz, well
        # inside 22.05 kHz, so a stricter ratio would promote every ordinary
        # CD rip to the next rate up.
        if cutoff_hz <= rate * 0.5 * 0.90:
            return rate
    return declared_sr


def effective_bit_depth(path: str) -> int:
    """Significant bits actually used, measured from decoded samples.

    Decode to s32, OR every sample together, and count the trailing zeros:
    a 16-bit master rewrapped as 24- or 32-bit leaves its low bits
    permanently zero. This is the only honest reading -- ffprobe reports
    what the CONTAINER declares, which is precisely the claim being tested.

    A dithered or noise-shaped upconversion defeats it and reports the
    higher depth. That is correct behaviour, not a gap: dither is real
    signal, and PRD 7.2 already states the honest limit that a motivated
    cheat defeats this in minutes.
    """
    raw = subprocess.run(
        ['ffmpeg', '-v', 'error', '-i', path, '-f', 's32le', '-ac', '1', '-'],
        capture_output=True, check=True).stdout
    if not raw:
        return 0
    samples = np.frombuffer(raw, dtype=np.int32)
    if samples.size == 0:
        return 0
    # Bitwise-OR the magnitudes. np.bitwise_or.reduce over int32 keeps the
    # sign bit, so take the unsigned view first.
    acc = int(np.bitwise_or.reduce(samples.view(np.uint32)))
    if acc == 0:
        return 0                      # digital silence: no evidence either way
    trailing = (acc & -acc).bit_length() - 1
    return max(1, 32 - trailing)
```

```python
# worker/app/lametag.py
# localchune — MIT licensed. See LICENSE.
# NOTE: the distributed combination is AGPL-3.0 because the analysis
# worker includes Essentia. LICENSE explains why.
"""The LAME/Xing/Info tag, in pure Python.

PRD 7.2 names mp3guessenc for this. We do not use it: it is a new GPL
binary, a new pinned sha256 and a new failure mode in an image that already
stages a 109-library Ubuntu-20.04 closure for Essentia, and the one field
classify_ancestor() actually consumes is 36 bytes at a computable offset.

The check this feeds is the cheapest kill in the whole forensics pass:
a transcoder running `lame -b 320` over a 128 kbps decode writes a tag
honestly claiming a 20.5 kHz lowpass while the audio brickwalls at 16.8 kHz.
The container lies; the audio does not.

EVERY parse failure returns None. A pool of files from other people contains
malformed MP3s, and a malformed MP3 is not an analysis failure.
"""
from dataclasses import dataclass

_BITRATES_V1_L3 = (0, 32, 40, 48, 56, 64, 80, 96, 112, 128, 160, 192, 224,
                   256, 320, 0)
_RATES_V1 = (44100, 48000, 32000, 0)


@dataclass(frozen=True)
class LameTag:
    lowpass_hz: int
    encoder_string: str
    vbr_method: str | None


def _id3v2_size(head: bytes) -> int:
    """Bytes to skip past an ID3v2 tag. Zero when there is none.

    The size is a 28-bit SYNCHSAFE integer: seven bits per byte, high bit
    always clear. Reading it as a plain big-endian int is the classic bug
    and lands the reader in the middle of the audio on any tag over 128 KB
    -- which is every file carrying embedded cover art.
    """
    if len(head) < 10 or head[:3] != b'ID3':
        return 0
    b = head[6:10]
    if any(x & 0x80 for x in b):
        return 0
    size = (b[0] << 21) | (b[1] << 14) | (b[2] << 7) | b[3]
    footer = 10 if (head[5] & 0x10) else 0
    return 10 + size + footer


def _frame_geometry(hdr: bytes) -> tuple[int, int] | None:
    """(side_info_bytes, sample_rate) for an MPEG-1 Layer III frame header."""
    if len(hdr) < 4 or hdr[0] != 0xFF or (hdr[1] & 0xE0) != 0xE0:
        return None
    version = (hdr[1] >> 3) & 0x03      # 3 = MPEG-1
    layer = (hdr[1] >> 1) & 0x03        # 1 = Layer III
    if version != 3 or layer != 1:
        return None                     # MPEG-2/2.5 use different offsets
    rate = _RATES_V1[(hdr[2] >> 2) & 0x03]
    if rate == 0 or _BITRATES_V1_L3[(hdr[2] >> 4) & 0x0F] == 0:
        return None
    mono = ((hdr[3] >> 6) & 0x03) == 3
    return (17 if mono else 32), rate


def read_lame_tag(path: str) -> LameTag | None:
    try:
        with open(path, 'rb') as fh:
            head = fh.read(10)
            fh.seek(_id3v2_size(head))
            # 8 KB is generous: the first frame follows the ID3v2 tag
            # immediately in every file a real encoder writes. Scanning
            # further would risk syncing on audio data that merely looks
            # like a frame header.
            buf = fh.read(8192)
    except OSError:
        return None

    for i in range(max(0, len(buf) - 4)):
        geom = _frame_geometry(buf[i:i + 4])
        if geom is None:
            continue
        side, _rate = geom
        x = i + 4 + side
        if buf[x:x + 4] not in (b'Xing', b'Info'):
            continue
        # Xing header: 4-byte magic, 4-byte flags, then the optional fields
        # the flags select. The LAME extension starts 120 bytes after the
        # magic regardless of which optional fields are present.
        lame = buf[x + 120:x + 156]
        if len(lame) < 36 or not lame[:4].startswith(b'LAME'):
            return None
        # Byte 21 of the extension is lowpass/100 -- 0xCD is 20.5 kHz.
        lowpass = lame[21] * 100
        if lowpass <= 0:
            return None
        vbr_code = lame[9] & 0x0F
        return LameTag(
            lowpass_hz=lowpass,
            encoder_string=lame[:9].decode('ascii', 'replace').strip(),
            vbr_method={1: 'cbr', 2: 'abr'}.get(vbr_code, 'vbr'),
        )
    return None
```

```python
"""content_sha256 -- PRD 6's layer 0.

The PRD calls this "free (already computed)". It is not: nothing has ever
computed it, and files.content_sha256 is NULL on every row in production.
It is nearly free HERE, because the container is the one place that already
holds the whole file on local disk: about 0.1 s for a 40 MB FLAC, against
the ~45 vCPU-s the rest of the analysis costs.

Streamed in 1 MiB chunks, never read whole: a 15-minute FLAC is ~150 MB and
the instance has 3 GiB it must not spend on a digest.
"""
import hashlib

_CHUNK = 1024 * 1024


def content_sha256(path: str) -> str:
    h = hashlib.sha256()
    with open(path, 'rb') as fh:
        while chunk := fh.read(_CHUNK):
            h.update(chunk)
    return h.hexdigest()
```

```sql
-- ============================================================
-- tracks -- the canonical, format-agnostic recording identity.
--
-- DELIBERATELY NARROW. PRD 4 draws about twenty canonical-metadata columns
-- here (artist, label, isrc, mbid, artwork_url, beat_grid...). Those are
-- M7's output. Creating them now as twenty always-NULL columns is a
-- placeholder that invites a reader, and M5 already renders artist and
-- title from raw_tags through display_artist()/display_title(). M7 adds its
-- own columns in its own migration.

  id                   uuid primary key default gen_random_uuid(),
  preferred_file_id    uuid references public.files(id),
  merged_into_track_id uuid references public.tracks(id),
  merged_at            timestamptz,
  created_at           timestamptz not null default now(),
  constraint no_self_merge check (merged_into_track_id is distinct from id)

  where merged_into_track_id is not null;

-- files.track_id has been a bare uuid since migration 06, whose comment
-- says "FK added in M4 when tracks exists". This is that.
alter table public.files
  add constraint files_track_fk foreign key (track_id) references public.tracks(id);
create index files_track_idx on public.files (track_id);

-- BACKFILL: one track per already-stored file. Without it the first real
-- merge has nothing to merge INTO, and every pre-M4 upload stays invisible
-- to a system whose whole job is comparing tracks.
--
-- 'stored' only. A file that never finished analysing has no fingerprint,
-- so minting an identity for it would create a track that can never be
-- compared to anything. Those get their track when they reach 'stored'.
with minted as (
  insert into public.tracks (id, preferred_file_id)
  select gen_random_uuid(), f.id
    from public.files f
   where f.state = 'stored' and f.track_id is null
  returning id, preferred_file_id
)
update public.files f set track_id = m.id
  from minted m where m.preferred_file_id = f.id;

-- ------------------------------------------------------------
-- The merge chain walker. EVERY read of a track id goes through this.
--
-- PRD 4: crates reference track_id and are NEVER rewritten by a merge or an
-- undo. A merge is one UPDATE, an undo is one UPDATE, and crates snap back
-- automatically because they resolve through here.
--
-- The depth cap is not decoration. No function in this milestone can build
-- a cycle, but a hand-run UPDATE can, and an unbounded loop inside a
-- function this widely called takes down every request that touches it.
-- 32 hops is far past any real chain and terminates instantly on a cycle.
-- ------------------------------------------------------------
create or replace function public.canonical_track_id(p_track_id uuid)
returns uuid language plpgsql stable security definer set search_path = '' as $$
declare
  v_id   uuid := p_track_id;
  v_next uuid;
  v_hops int  := 0;
begin
  if v_id is null then
    return null;                      -- an unassigned file is not an error
  end if;
  loop
    select t.merged_into_track_id into v_next from public.tracks t where t.id = v_id;
    exit when v_next is null or v_hops >= 32;
    v_id := v_next;
    v_hops := v_hops + 1;
  end loop;
  return v_id;
end $$;
revoke execute on function public.canonical_track_id(uuid) from public, anon;
grant  execute on function public.canonical_track_id(uuid) to authenticated, service_role;
```

```sql
-- ------------------------------------------------------------
-- analysis_requeue -- reopen stored files for re-analysis.
--
-- Needed because Task 1 changes what an analysis PRODUCES, and the only way
-- to fill forensics on an existing row is to run the container again.
-- analysis_begin() accepts 'received' and 'analysing' only, so a 'stored'
-- file is unreachable without this.
--
-- stored -> 'received', not straight to 'analysing': 'received' is the
-- state that MEANS "needs analysis", and the maintenance Worker's existing
-- :31 cron already re-enqueues anything sitting in it. No new producer, no
-- new queue, no new cron.
--
-- The cost of a requeue is real -- about 45 vCPU-s per file -- and the file
-- leaves pool_list() (which filters state = 'stored') until it returns.
-- p_file_ids is explicit, never a predicate: "requeue everything" is one
-- typo away from re-analysing the whole pool.
-- ------------------------------------------------------------
create or replace function public.analysis_requeue(p_file_ids uuid[])
returns table (file_id uuid, r2_key text)
language plpgsql security definer set search_path = '' as $$
begin
  if coalesce(array_length(p_file_ids, 1), 0) = 0 then
    return;
  end if;
  if array_length(p_file_ids, 1) > 500 then
    raise exception 'analysis_requeue: refusing % files in one call', array_length(p_file_ids, 1)
      using errcode = '22023';
  end if;
  return query
    update public.files f
       set state = 'received', state_changed_at = now()
     where f.id = any (p_file_ids) and f.state = 'stored'
    returning f.id, f.r2_key;
end $$;
revoke execute on function public.analysis_requeue(uuid[]) from public, anon, authenticated;
grant  execute on function public.analysis_requeue(uuid[]) to service_role;
```

### Task 3: The BER scorer — one pure module, property-tested

The whole milestone reduces to one number, and this is where it is computed. Pure functions over `Uint32Array`: no fetch, no Supabase, no DOM, so it is unit-testable under the only environment this repo has.

**One naming trap to record before writing a line of it.** The column is called `fp_compressed_b64`, but `worker/app/fingerprint.py` does `struct.pack(f'<{len(raw)}I', *raw)` and base64-encodes that. It is **raw little-endian `uint32`, not chromaprint's compressed form.** A 6-minute track is 2,886 frames → 11.5 KB packed → ~15.4 KB of base64, where PRD §6 assumed ~4 KB compressed. At 2,000 tracks that is ~31 MB in Postgres, which is fine, so the column is **not** renamed — it is live, migration 09 is applied, and a rename would be a migration and a code change to fix a comment. The decoder here must read raw LE `uint32` and the test asserts it, so nobody re-derives the wrong thing from the name.

- Create: `src/lib/ber.ts`, `src/lib/ber.test.ts`

**Interfaces:**
- Produces: `unpackFingerprint(b64): Uint32Array`, `bitErrorRate(a, b, offset): {ber, overlap}`, `sweepOffsets(a, b, maxOffset): {score, bestOffset, overlapFrames}`, `perSecondBer(a, b, offset): number[]`, `scoreCandidate(probe, candidate): CandidateScore`, `FRAMES_PER_SECOND = 8`, `MAX_OFFSET_FRAMES = 80`.

```ts
/** Deterministic pseudo-fingerprint. Never Math.random in a test that
 *  asserts a numeric bound — a flaky scorer test would be worse than none. */
function synth(n: number, seed = 1): Uint32Array {
  const out = new Uint32Array(n)
  let s = seed >>> 0
  for (let i = 0; i < n; i++) {
    s = (Math.imul(s, 1664525) + 1013904223) >>> 0
    out[i] = s
  }
  return out
}

function flipBits(a: Uint32Array, everyNth: number): Uint32Array {
  const out = Uint32Array.from(a)
  for (let i = 0; i < out.length; i += everyNth) out[i] ^= 1 << (i % 32)
  return out
}
```

```ts
// src/lib/ber.ts
// localchune — MIT licensed. See LICENSE.
// NOTE: the distributed combination is AGPL-3.0 because the analysis
// worker includes Essentia. LICENSE explains why.

/**
 * Chromaprint fingerprint comparison — PRD §6 layer 2.
 *
 * Pure: two Uint32Arrays in, a score out. No fetch, no Supabase, no DOM, so
 * it runs identically in the analysis consumer, in the maintenance
 * backstop, and under Vitest's node environment.
 *
 * THE STORED FORMAT IS RAW, NOT COMPRESSED. The column is named
 * `fp_compressed_b64`, but worker/app/fingerprint.py packs the raw frames
 * with struct '<{n}I' and base64s the result. The name predates the
 * implementation and is not worth a migration; this comment and the first
 * test in ber.test.ts are the record.
 */

/** fpcalc's frame rate. M3 Task 4 measured 2,886 frames on a 6:00 fixture. */
export const FRAMES_PER_SECOND = 8

/** ±10 seconds of alignment search. PRD §6. */
export const MAX_OFFSET_FRAMES = 80

/**
 * Under about eight seconds of overlap a score means nothing: two unrelated
 * tracks can agree over a short window by chance, and PRD §6's bands were
 * never calibrated against one. Below this the answer is 0, not a number.
 */
export const MIN_OVERLAP_FRAMES = 64

export interface Probe { fileId: string; frames: Uint32Array }
export interface Candidate extends Probe {
  trackId: string | null
  durationMs: number | null
}
export interface CandidateScore {
  candidateFileId: string
  candidateTrackId: string | null
  score: number
  bestOffset: number
  overlapFrames: number
  perSecondBer: number[]
}

/** Base64 → bytes, without Buffer: Workers have atob, Node 22 has it too. */
function b64ToBytes(b64: string): Uint8Array {
  const bin = atob(b64)
  const out = new Uint8Array(bin.length)
  for (let i = 0; i < bin.length; i++) out[i] = bin.charCodeAt(i)
  return out
}

export function unpackFingerprint(b64: string): Uint32Array {
  if (!b64) return new Uint32Array(0)
  const bytes = b64ToBytes(b64)
  const n = Math.floor(bytes.length / 4)
  const out = new Uint32Array(n)
  // DataView with littleEndian=true, never a Uint32Array view over the
  // buffer: the byte offset is not guaranteed to be 4-aligned, and host
  // endianness is not a thing to bet a dedup decision on.
  const view = new DataView(bytes.buffer, bytes.byteOffset, bytes.byteLength)
  for (let i = 0; i < n; i++) out[i] = view.getUint32(i * 4, true)
  return out
}

/** The inverse, for tests and for nothing else. */
export function packForTest(frames: Uint32Array): string {
  const bytes = new Uint8Array(frames.length * 4)
  const view = new DataView(bytes.buffer)
  frames.forEach((v, i) => view.setUint32(i * 4, v, true))
  let bin = ''
  for (const b of bytes) bin += String.fromCharCode(b)
  return btoa(bin)
}

/** Hamming weight of a 32-bit word. The standard SWAR popcount. */
function popcount32(x: number): number {
  x = x - ((x >>> 1) & 0x55555555)
  x = (x & 0x33333333) + ((x >>> 2) & 0x33333333)
  x = (x + (x >>> 4)) & 0x0f0f0f0f
  return (Math.imul(x, 0x01010101) >>> 24)
}

/**
 * Fraction of differing bits over the overlapping region.
 *
 * `offset` is how far b is shifted relative to a: a positive offset means b
 * starts later, i.e. a[i + offset] is compared with b[i].
 */
export function bitErrorRate(
  a: Uint32Array, b: Uint32Array, offset: number,
): { ber: number; overlap: number } {
  const start = Math.max(0, -offset)
  const end = Math.min(b.length, a.length - offset)
  const overlap = end - start
  if (overlap <= 0) return { ber: 1, overlap: 0 }
  let bits = 0
  for (let i = start; i < end; i++) bits += popcount32((a[i + offset] ^ b[i]) >>> 0)
  return { ber: bits / (overlap * 32), overlap }
}

/**
 * The offset sweep. score = 1 − BER at the best alignment.
 *
 * ±80 frames is ±10 seconds, which covers the real cases: a rip that starts
 * a beat early, a radio edit trimmed at the head, a CD track with a
 * different pregap. It does NOT cover a vinyl rip at a different playback
 * speed — chromaprint is not robust to tempo shift and PRD §6 accepts those
 * duplicates rather than pretending otherwise.
 */
export function sweepOffsets(
  a: Uint32Array, b: Uint32Array, maxOffset = MAX_OFFSET_FRAMES,
): { score: number; bestOffset: number; overlapFrames: number } {
  if (a.length === 0 || b.length === 0) {
    return { score: 0, bestOffset: 0, overlapFrames: 0 }
  }
  let best = { ber: 1, overlap: 0, offset: 0 }
  for (let off = -maxOffset; off <= maxOffset; off++) {
    const { ber, overlap } = bitErrorRate(a, b, off)
    if (overlap === 0) continue
    if (ber < best.ber) best = { ber, overlap, offset: off }
  }
  if (best.overlap < MIN_OVERLAP_FRAMES) {
    return { score: 0, bestOffset: best.offset, overlapFrames: best.overlap }
  }
  return {
    score: 1 - best.ber,
    bestOffset: best.offset,
    overlapFrames: best.overlap,
  }
}

/**
 * BER per second of overlap — the review UI's divergence strip.
 *
 * A matching body with a divergent first thirty seconds is a different
 * intro edit, not a different track. That distinction is invisible in a
 * single number and obvious in this array, which is the entire reason PRD
 * §6 asks for it.
 */
export function perSecondBer(
  a: Uint32Array, b: Uint32Array, offset: number,
): number[] {
  const start = Math.max(0, -offset)
  const end = Math.min(b.length, a.length - offset)
  if (end <= start) return []
  const out: number[] = []
  for (let i = start; i < end; i += FRAMES_PER_SECOND) {
    const stop = Math.min(i + FRAMES_PER_SECOND, end)
    let bits = 0
    for (let j = i; j < stop; j++) bits += popcount32((a[j + offset] ^ b[j]) >>> 0)
    out.push(bits / ((stop - i) * 32))
  }
  return out
}

export function scoreCandidate(probe: Probe, candidate: Candidate): CandidateScore {
  const { score, bestOffset, overlapFrames } =
    sweepOffsets(probe.frames, candidate.frames)
  return {
    candidateFileId: candidate.fileId,
    candidateTrackId: candidate.trackId,
    score: Number(score.toFixed(6)),
    bestOffset,
    overlapFrames,
    // Rounded to three places: this array is ~360 numbers per decision and
    // is stored per decision. Full float precision on a display strip is
    // bytes spent on digits nobody can see.
    perSecondBer: perSecondBer(probe.frames, candidate.frames, bestOffset)
      .map((v) => Number(v.toFixed(3))),
  }
}
```

- Consumed by: `workers/analysis/src/dedup.ts` (Task 5) and `dedup_resolve()` (Task 6), which re-runs `dedup_candidates()` **inside** the advisory lock.

**Four gates, and why each one is there:**

1. **`algo_version` equality.** A `cp-1.5.1` fingerprint and a `cp-1.6.0` fingerprint of identical audio are different numbers. M3 Task 8 caught this in the image build — Debian trixie ships chromaprint 1.5.1 while dev had 1.6.0 — and pinned fpcalc by sha256 for exactly this reason. Without the gate, a version bump silently scores every old track as unrelated to every new one.
2. **GIN overlap** on `query_items`, using **`array_ops`**, the built-in opclass. PRD §6 writes `gin__int_ops`, which is `intarray`'s and accepts `int4[]` only; the column is `bigint[]`.
3. **±10 s duration gate**, on `fingerprints.duration_s` — which comes from fpcalc's own decode, not from a container header. If any path ever fills it from tags, this gate silently drops true duplicates with no error and no alert (migration 06's column comment says the same thing about `files.duration_ms`).
4. **`dedup_negatives` exclusion**, so a human's "these are different" is never re-asked.

Plus the **fallback**: if the GIN query returns nothing, a duration-only scan capped at 400 rows. PRD §6 calls it *"cheap insurance that degrades gracefully"* — it is what catches a pair whose `query_items` windows both landed in differing intros, which is the known weakness of the two-window scheme.

```sql
-- supabase/migrations/20260729140100_16_dedup_retrieval.sql
-- localchune — MIT licensed. See LICENSE.
-- NOTE: the distributed combination is AGPL-3.0 because the analysis
-- worker includes Essentia. LICENSE explains why.
--
-- M4 Task 4. Read-only retrieval. Decides nothing, writes nothing.

-- ============================================================
-- Indexes.
--
-- array_ops, NOT gin__int_ops. PRD §6 writes `gin (query_items
-- gin__int_ops)`, but gin__int_ops belongs to the intarray extension and
-- accepts int4[] only -- the shipped column is bigint[] and the create
-- would fail outright.
--
-- The masked items are all < 2^20 and WOULD fit int4: the bigint[] choice
-- in migration 09 was made for the RAW fingerprint values, which M3 Task 4
-- measured above 2^31. Reaching intarray from here would mean a second,
-- generated int4[] column -- the same data written twice to win a constant
-- factor on a table of two thousand rows. PRD §6 forbids exactly that
-- class of optimisation, and array_ops supports && on any array type.
--
-- TRIPWIRE: if the pool ever passes ~100k fingerprints AND the candidate
-- query stops being sub-10ms, revisit -- in that order. Not before.
-- ============================================================
create index if not exists fingerprints_qi_gin
  on public.fingerprints using gin (query_items);
create index if not exists fingerprints_dur_idx
  on public.fingerprints (algo_version, duration_s);

-- ------------------------------------------------------------
-- |a ∩ b|. There is no built-in array intersection for bigint[] without
-- intarray, and the candidate ranking needs the count.
--
-- Sizes here are ~200-400 items per side over at most 400 candidates, so
-- the set-based INTERSECT is the right shape: readable, and index-free work
-- on data already in memory.
-- ------------------------------------------------------------
create or replace function public.qi_overlap(a bigint[], b bigint[])
returns int language sql immutable parallel safe set search_path = '' as $$
  select coalesce((
    select count(*)::int
      from (select unnest(a) intersect select unnest(b)) s), 0);
$$;
revoke execute on function public.qi_overlap(bigint[], bigint[])
  from public, anon, authenticated;

-- ------------------------------------------------------------
-- The candidate query. PRD §6: GIN overlap plus a ±10 s duration gate,
-- top N by shared items, with a duration-only fallback.
--
-- The caller decompresses at most N fingerprints and runs the offset sweep.
-- Everything expensive stays OUT of this function on purpose: this is the
-- ~2 ms half of the read-compute-verify-write protocol, and dedup_resolve()
-- re-runs it verbatim inside the advisory lock.
--
-- Every reference is table-qualified. In a plpgsql `returns table` the
-- output columns are variables, so a bare `score` or `duration_s` would be
-- ambiguous and raise 42702 at RUNTIME. Migration 08 hit exactly this.
-- ------------------------------------------------------------
create or replace function public.dedup_candidates(
  p_file_id uuid, p_limit int default 25
) returns table (
  candidate_file_id  uuid,
  candidate_track_id uuid,
  fp_compressed_b64  text,
  fp_sha256          text,
  shared_items       int,
  duration_delta_ms  int,
  bpm                real,
  key_camelot        text,
  quality_tier       smallint,
  via                text
)
language plpgsql stable security definer set search_path = '' as $$
declare
  v_items   bigint[];
  v_algo    text;
  v_dur_s   int;
  v_gate    int  := 10;
  v_limit   int  := least(greatest(coalesce(p_limit, 25), 1), 100);
  v_probe_ms int;
begin
  select g.query_items, g.algo_version, g.duration_s
    into v_items, v_algo, v_dur_s
    from public.fingerprints g where g.file_id = p_file_id;
  if v_algo is null then
    return;                       -- no fingerprint yet: nothing to compare
  end if;

  select c.duration_gate_s into v_gate
    from public.dedup_config c where c.algo_version = v_algo;
  v_gate := coalesce(v_gate, 10);

  select a.duration_ms into v_probe_ms
    from public.audio_analysis a where a.file_id = p_file_id;

  return query
  with base as (
    select g.file_id, f.track_id, g.query_items, g.fp_compressed_b64,
           g.fp_sha256, g.duration_s,
           a.duration_ms, a.bpm, a.key_camelot, a.quality_tier
      from public.fingerprints g
      join public.files f          on f.id = g.file_id
      left join public.audio_analysis a on a.file_id = g.file_id
     where g.file_id <> p_file_id
       -- Two fingerprints from different chromaprint builds are not
       -- comparable. M3 Task 8: Debian ships 1.5.1, dev had 1.6.0, and the
       -- image pins 1.6.0 by sha256 precisely so this gate stays quiet.
       and g.algo_version = v_algo
       -- fpcalc's own decoded duration, never a container header.
       and abs(g.duration_s - v_dur_s) <= v_gate
       and f.state = any (public.pool_visible_states())
       and not exists (
         select 1 from public.dedup_negatives n
          where n.file_lo = least(p_file_id, g.file_id)
            and n.file_hi = greatest(p_file_id, g.file_id))
  ),
  hit as (
    select b.*, public.qi_overlap(v_items, b.query_items) as shared, 'gin'::text as src
      from base b
     where b.query_items && v_items
     order by public.qi_overlap(v_items, b.query_items) desc,
              -- BPM is a TIE-BREAK inside an already-qualifying set, never
              -- a gate and never part of a score. PRD §6: the fingerprint
              -- decides; metadata only assists ranking.
              abs(coalesce(b.bpm, 0) - 0) desc,
              b.file_id
     limit v_limit
  ),
  fallback as (
    -- "If the GIN query returns nothing, fall back to a duration-only scan
    -- capped at 400 candidates -- cheap insurance that degrades
    -- gracefully." (PRD §6.) This is what catches a pair whose two
    -- query_items windows both landed in differing intros, which is the
    -- known weakness of the two-window scheme.
    select b.*, 0 as shared, 'duration'::text as src
      from base b
     where not exists (select 1 from hit)
     order by abs(b.duration_s - v_dur_s), b.file_id
     limit least(v_limit * 16, 400)
  ),
  merged as (select * from hit union all select * from fallback)
  select m.file_id, m.track_id, m.fp_compressed_b64, m.fp_sha256,
         m.shared,
         case when v_probe_ms is null or m.duration_ms is null then null
              else m.duration_ms - v_probe_ms end,
         m.bpm, m.key_camelot, m.quality_tier, m.src
    from merged m;
end $$;
revoke execute on function public.dedup_candidates(uuid, int)
  from public, anon, authenticated;
grant  execute on function public.dedup_candidates(uuid, int) to service_role;

-- ------------------------------------------------------------
-- The backstop cron's query. Files that finished analysis, have a usable
-- fingerprint, and never got a track.
--
-- This is what makes the consumer's dedup step safe to treat as
-- best-effort: a crash between persist() and resolve() costs an hour of
-- latency, never a lost assignment.
--
-- state_changed_at, never created_at -- created_at is when the row was
-- minted, before the bytes moved.
-- ------------------------------------------------------------
create or replace function public.dedup_pending(p_limit int default 50)
returns table (file_id uuid, algo_version text)
language sql stable security definer set search_path = '' as $$
  select f.id, g.algo_version
    from public.files f
    join public.fingerprints g on g.file_id = f.id
   where f.state = 'stored'
     and f.track_id is null
     and f.state_changed_at < now() - interval '5 minutes'
   order by f.state_changed_at
   limit least(greatest(p_limit, 1), 200);
$$;
revoke execute on function public.dedup_pending(int) from public, anon, authenticated;
grant  execute on function public.dedup_pending(int) to service_role;

-- ------------------------------------------------------------
-- dedup_is_upgrade -- worker/app/forensics.py's is_upgrade(), in SQL.
--
-- A SECOND IMPLEMENTATION OF ONE RULE, deliberately. The merge decision
-- happens inside a transaction holding an advisory lock; the alternative is
-- a round trip to the container for a verdict that needs no audio at all,
-- which is worse. The cost is paid down by replaying the Python version's
-- own test vectors in pgTAP -- if the two ever disagree, a test fails.
--
-- Requires a MARGIN and a HARD monotone win, per PRD §11's earning rule:
-- "not just a higher score".
--
-- NULL on either side returns false. Absence of evidence is not an upgrade,
-- and until Task 1's backfill lands that is the common case.
-- ------------------------------------------------------------
create or replace function public.dedup_is_upgrade(a jsonb, b jsonb)
returns boolean language plpgsql immutable set search_path = '' as $$
declare
  sa real; sb real; hard boolean;
begin
  if a is null or b is null
     or a ->> 'tier' is null or b ->> 'tier' is null then
    return false;
  end if;
  if coalesce((b ->> 'clipped_pct')::real, 0) > 0.001
     and coalesce((a ->> 'clipped_pct')::real, 0) <= 0.001 then
    return false;                                  -- newly clipped
  end if;
  sa := public.dedup_quality_score(a);
  sb := public.dedup_quality_score(b);
  if sb - sa < 8 then
    return false;                                  -- not better by enough
  end if;
  hard := (b ->> 'tier')::int > (a ->> 'tier')::int
       or (b ->> 'cutoff_hz')::int >= (a ->> 'cutoff_hz')::int + 1500
       or (coalesce((a ->> 'inferred_kbps')::int, 0) > 0
           and (b ->> 'tier')::int = 5);
  if not hard then
    return false;
  end if;
  if coalesce((b ->> 'lame_disagrees')::boolean, false)
     and (b ->> 'cutoff_hz')::int <= (a ->> 'cutoff_hz')::int then
    return false;      -- confirmed lossy ancestor at no better bandwidth
  end if;
  return true;
end $$;
revoke execute on function public.dedup_is_upgrade(jsonb, jsonb)
  from public, anon, authenticated;
grant  execute on function public.dedup_is_upgrade(jsonb, jsonb) to service_role;
```

`dedup_quality_score(jsonb)` is the same migration and is a line-for-line port of `worker/app/forensics.py:quality_score`, including the two deliberate omissions recorded there: **no DR penalty** (it encodes an audiophile preference this pool does not share — a loud DR5 remaster may be exactly the club-ready copy a DJ wants), and `clipped_pct` treated as a **threshold** rather than a percentage, because M3 Task 6 established it is an Abs-Peak-recurrence proxy and not a clip count.

```ts
// workers/analysis/src/dedup.ts
// localchune — MIT licensed. See LICENSE.
// NOTE: the distributed combination is AGPL-3.0 because the analysis
// worker includes Essentia. LICENSE explains why.

/**
 * The matcher — PRD §6 layers 0–2, run in the queue consumer.
 *
 * WHY HERE. The container holds no credential by design and cannot query
 * Postgres. Postgres cannot run an offset sweep without a C extension
 * hosted Supabase will not install. A standalone cron adds an hour of
 * latency for no gain. The consumer already holds the service_role key, the
 * fresh fingerprint and an R2 binding.
 *
 * WHY BEST-EFFORT. handleMessage() acks once persist() succeeds. A retry
 * after that point calls analysis_begin(), receives 'stored', and acks as
 * "not claimable" — the dedup would never run — while a retry of the whole
 * message would re-run ~45 vCPU-s of container analysis to recompute a
 * fingerprint already in the database. So a failure here is logged and
 * acked, and public.dedup_pending() + the 47-past cron is the guarantee.
 * That cron is load-bearing, not decorative.
 */
import { scoreCandidate, unpackFingerprint } from '../../../src/lib/ber'

/**
 * The most candidates we will sweep. dedup_candidates' duration-only
 * fallback can legitimately return up to 400 rows; 400 × 2,886 frames × 161
 * offsets is ~185M popcounts, which is an order of magnitude past what the
 * "score it in the consumer" decision was argued on. The fallback exists to
 * catch a pair the GIN missed, and that pair is near the top of a
 * duration-ordered list or it is not there at all.
 */
export const MAX_SWEEP_CANDIDATES = 50

export interface ProbeFingerprint {
  fp_compressed_b64: string
  fp_sha256: string
  algo_version: string
}
export interface CandidateRow {
  candidate_file_id: string
  candidate_track_id: string | null
  fp_compressed_b64: string
  fp_sha256: string
  shared_items: number
  duration_delta_ms: number | null
}
export interface ScoredCandidate {
  candidateFileId: string
  candidateTrackId: string | null
  layer: 'fp_sha256' | 'ber'
  score: number
  bestOffset: number
  overlapFrames: number
  sharedItems: number
  durationDeltaMs: number | null
  perSecondBer: number[]
}
export interface ResolveResult {
  action: string
  track_id: string | null
  reclaim_r2_key?: string | null
}
export interface DedupDeps {
  probeFingerprint(fileId: string): Promise<ProbeFingerprint | null>
  candidates(fileId: string): Promise<CandidateRow[]>
  resolve(fileId: string, scored: ScoredCandidate[], algo: string): Promise<ResolveResult>
  reclaim(r2Key: string): Promise<void>
}
export interface DedupOutcome {
  ok: boolean
  action?: string
  trackId?: string | null
  reason?: string
  warning?: string
}

export async function runDedup(
  fileId: string, deps: DedupDeps,
): Promise<DedupOutcome> {
  const probe = await deps.probeFingerprint(fileId)
  if (probe === null || !probe.fp_compressed_b64) {
    // A file with no fingerprint is not a failure of this job. A degraded
    // analysis is data; it simply has nothing to compare.
    return { ok: false, reason: `${fileId}: no fingerprint, nothing to compare` }
  }

  const probeFrames = unpackFingerprint(probe.fp_compressed_b64)
  const rows = (await deps.candidates(fileId)).slice(0, MAX_SWEEP_CANDIDATES)

  const scored: ScoredCandidate[] = rows.map((row) => {
    // Layer 0b: identical fingerprints. PRD §6 step 4 — "this is the common
    // 'same rip, different tags' case, and it's free". Sweeping 161 offsets
    // to rediscover a known answer is the opposite of free.
    if (row.fp_sha256 && row.fp_sha256 === probe.fp_sha256) {
      return {
        candidateFileId: row.candidate_file_id,
        candidateTrackId: row.candidate_track_id,
        layer: 'fp_sha256', score: 1, bestOffset: 0,
        overlapFrames: probeFrames.length,
        sharedItems: row.shared_items,
        durationDeltaMs: row.duration_delta_ms,
        perSecondBer: [],
      }
    }
    const s = scoreCandidate(
      { fileId, frames: probeFrames },
      { fileId: row.candidate_file_id, trackId: row.candidate_track_id,
        frames: unpackFingerprint(row.fp_compressed_b64),
        durationMs: null })
    return {
      candidateFileId: s.candidateFileId,
      candidateTrackId: s.candidateTrackId,
      layer: 'ber', score: s.score, bestOffset: s.bestOffset,
      overlapFrames: s.overlapFrames,
      sharedItems: row.shared_items,
      durationDeltaMs: row.duration_delta_ms,
      perSecondBer: s.perSecondBer,
    }
  })

  // Everything above ran OUTSIDE any transaction, which is the whole point
  // of PRD §6's protocol: the expensive part must not hold a lock. resolve()
  // takes the advisory lock and RE-RUNS the candidate query inside it.
  const result = await deps.resolve(fileId, scored, probe.algo_version)

  let warning: string | undefined
  if (result.reclaim_r2_key) {
    try {
      await deps.reclaim(result.reclaim_r2_key)
    } catch (e) {
      // The database decision already committed and the row already says
      // rejected_redundant. A leftover object is a phantom, which the
      // nightly reconcile reports. Failing the job here would be undoing a
      // correct decision because a delete did not land.
      warning = `reclaim of ${result.reclaim_r2_key} failed: ${String(e)}`
    }
  }
  return { ok: true, action: result.action, trackId: result.track_id, warning }
}
```

### Task 6: Migration 17 — resolve, merge, undo

The write side. Everything here runs inside one transaction holding one advisory lock, and every merge leaves behind enough to undo itself.

**Files:**
- Create: `supabase/migrations/20260729140200_17_dedup_rpc.sql`
- Test: `supabase/tests/dedup_merge.sql`

**Interfaces:**
- Produces: `forensics_json(uuid)`, `dedup_dominated(jsonb, jsonb)`, `dedup_resolve(uuid, jsonb, text)`, `merge_tracks(uuid, uuid, bigint, text)`, `undo_merge(bigint)`, `recent_merges(int)`.
- Consumed by: `workers/analysis/src/dedup.ts`, the review UI (Task 7), the merges feed (Task 7).

**The concurrency protocol, and why neither half is optional** (PRD §6). A unique constraint cannot express approximate equivalence over a fuzzy score. A lock alone does not help, because the expensive candidate scan happens *before* it. So: score outside any transaction (Task 5), then `BEGIN` → `pg_advisory_xact_lock(hashtext('localchune.track_assign'))` → **re-run the candidate query inside the lock** → write → `COMMIT`. If a track appeared between the two runs that now scores ≥ `t_same`, use it instead of minting a second one.

One **global** advisory lock, not a sharded one. The critical section is ~10 ms, so 400 concurrent files serialise in about four seconds. Sharding by duration bucket would be *worse*: two encodes of one track can straddle a boundary and reintroduce the race the lock exists to close. `pg_advisory_xact_lock`, never the session-level `pg_advisory_lock` — a definer function that leaks a session lock poisons the connection for every later request on it.

```sql
-- supabase/migrations/20260729140200_17_dedup_rpc.sql
-- localchune — MIT licensed. See LICENSE.
-- NOTE: the distributed combination is AGPL-3.0 because the analysis
-- worker includes Essentia. LICENSE explains why.
--
-- M4 Task 6. The write side. Every path through here either assigns a
-- track or mints one; none of them can leave a stored file without one.

-- ------------------------------------------------------------
-- dedup_resolve -- read, compute, RE-VERIFY UNDER LOCK, write.
--
-- p_scored is the result of an offset sweep the CALLER already ran outside
-- any transaction (workers/analysis/src/dedup.ts). PRD §6's protocol:
--   1. outside a transaction: fingerprint, GIN query, score  (hundreds of ms)
--   2. take the lock
--   3. INSIDE the lock, re-run the candidate query (~2 ms). If a track
--      appeared since step 1 that now scores >= t_same, use it instead of
--      creating one.
--   4. also inside the lock: an exact content_sha256 or fp_sha256 match
--      reuses its track and skips scoring entirely.
--
-- ONE GLOBAL LOCK, not a sharded one. The critical section is ~10 ms, so
-- 400 concurrent files serialise in about four seconds. Sharding by
-- duration bucket would be WORSE: two encodes of one track can straddle a
-- boundary and reintroduce the exact race this closes.
--
-- pg_advisory_xact_lock, NEVER pg_advisory_lock: a session-level lock
-- leaked out of a definer function poisons that connection for every later
-- request served on it.
-- ------------------------------------------------------------
create or replace function public.dedup_resolve(
  p_file_id uuid, p_scored jsonb, p_algo_version text
) returns table (action text, track_id uuid, reclaim_r2_key text)
language plpgsql security definer set search_path = '' as $$
declare
  v_cfg      public.dedup_config%rowtype;
  v_best     jsonb;
  v_score    real;
  v_win_file uuid;
  v_win_trk  uuid;
  v_layer    text := 'ber';
  v_new_trk  uuid;
  v_action   text;
  v_reclaim  text;
  v_probe_f  jsonb;
  v_inc_f    jsonb;
  v_decision bigint;
  v_merge_id bigint;
begin
  perform set_config('statement_timeout', '5s', true);
  perform pg_advisory_xact_lock(hashtext('localchune.track_assign'));

  select * into v_cfg from public.dedup_config c where c.algo_version = p_algo_version;
  if v_cfg.algo_version is null then
    -- An unknown algo_version means an image shipped fingerprints nobody
    -- calibrated. Minting a track is safe; guessing thresholds is not.
    raise warning 'dedup_resolve: no dedup_config for %, treating as distinct',
      p_algo_version;
  end if;

  -- LAYER 0a, inside the lock: byte-identical bytes. Free, and it is the
  -- only path that reaches a DIFFERENT uploader's existing file.
  select f2.id, f2.track_id into v_win_file, v_win_trk
    from public.files f1
    join public.files f2
      on f2.content_sha256 = f1.content_sha256 and f2.id <> f1.id
   where f1.id = p_file_id
     and f1.content_sha256 is not null
     and f2.state = any (public.pool_visible_states())
   order by f2.created_at
   limit 1;
  if v_win_file is not null then
    v_layer := 'content_sha256';
    v_score := 1.0;
  else
    -- LAYER 1+2: the caller's best score, re-checked against the candidate
    -- query as it stands NOW.
    select s into v_best
      from jsonb_array_elements(coalesce(p_scored, '[]'::jsonb)) s
     order by (s ->> 'score')::real desc
     limit 1;
    v_score := coalesce((v_best ->> 'score')::real, 0);
    if v_score >= coalesce(v_cfg.t_same, 0.90) then
      v_win_file := (v_best ->> 'candidateFileId')::uuid;
      v_win_trk  := public.canonical_track_id((v_best ->> 'candidateTrackId')::uuid);
      v_layer    := coalesce(v_best ->> 'layer', 'ber');
      -- The re-verify. If this candidate stopped qualifying while we were
      -- scoring -- demoted, deleted, or ruled different by a human in the
      -- meantime -- do not merge into it.
      if not exists (
        select 1 from public.dedup_candidates(p_file_id, v_cfg.candidate_limit) c
         where c.candidate_file_id = v_win_file
      ) then
        v_win_file := null;
        v_win_trk  := null;
      end if;
    end if;
  end if;

  -- Record the decision BEFORE acting on it. An append-only ledger whose
  -- rows appear only for the branches that succeeded is not a ledger.
  if v_best is not null or v_win_file is not null then
    update public.match_decisions d set superseded_at = now()
     where d.probe_file_id = p_file_id
       and d.candidate_file_id = coalesce(v_win_file, (v_best ->> 'candidateFileId')::uuid)
       and d.superseded_at is null;
    insert into public.match_decisions
      (probe_file_id, candidate_file_id, candidate_track_id, algo_version,
       layer, score, band, best_offset_frames, overlap_frames, shared_items,
       duration_delta_ms, per_second_ber, thresholds, action)
    values (
      p_file_id,
      coalesce(v_win_file, (v_best ->> 'candidateFileId')::uuid),
      v_win_trk,
      p_algo_version,
      v_layer,
      v_score,
      case when v_score >= coalesce(v_cfg.t_same, 0.90)     then 'same'
           when v_score >= coalesce(v_cfg.t_probable, 0.70) then 'probable'
           when v_score >= coalesce(v_cfg.t_related, 0.40)  then 'related'
           else 'different' end,
      (v_best ->> 'bestOffset')::int,
      (v_best ->> 'overlapFrames')::int,
      (v_best ->> 'sharedItems')::int,
      (v_best ->> 'durationDeltaMs')::int,
      public.jsonb_real_array(v_best -> 'perSecondBer'),
      -- The exact thresholds THIS decision used. PRD §6: a threshold change
      -- must not retroactively make a past decision unexplainable.
      to_jsonb(v_cfg),
      'pending')
    returning id into v_decision;
  end if;

  -- ---------- act on the band ----------
  if v_win_file is not null then
    -- The incumbent must have an identity to join. A pre-M4 row the
    -- backfill missed would otherwise leave the WINNER identity-less.
    if v_win_trk is null then
      insert into public.tracks (preferred_file_id) values (v_win_file)
        returning id into v_win_trk;
      update public.files set track_id = v_win_trk where id = v_win_file;
    end if;

    -- MINT THE PROBE ITS OWN TRACK, THEN MERGE THAT TRACK AWAY.
    --
    -- The shortcut -- point files.track_id straight at the winner -- is one
    -- UPDATE cheaper and it is wrong, because it leaves NO track_merges
    -- row. An automatic assignment would then be the one collapse in the
    -- system with no undo payload and no entry in the merges feed, which is
    -- exactly the case PRD §15 names first: "wrong auto-merges destroy
    -- someone's crates", mitigated by "merges reversible by design" plus a
    -- feed so wrong ones get noticed. A silent assignment is neither.
    --
    -- Going through merge_tracks() means there is ONE collapse path, one
    -- undo, and one feed, whether the decision was made by the matcher or
    -- by a person on a review row.
    --
    -- The probe's existing track is REUSED when it has one. dedup_pending()
    -- re-runs the matcher over files that already went through this
    -- function once, and minting a second identity for the same file every
    -- time would leave a trail of orphan tracks nothing points at.
    select f.track_id into v_new_trk from public.files f where f.id = p_file_id;
    if v_new_trk is null then
      insert into public.tracks (preferred_file_id) values (p_file_id)
        returning id into v_new_trk;
      update public.files f set track_id = v_new_trk where f.id = p_file_id;
    else
      v_new_trk := public.canonical_track_id(v_new_trk);
    end if;
    if v_new_trk = v_win_trk then
      -- Already collapsed, by an earlier delivery of the same message.
      -- Queues is at-least-once and this function must be idempotent.
      return query select 'already_merged'::text, v_win_trk, null::text;
    end if;
    v_merge_id := public.merge_tracks(v_new_trk, v_win_trk, v_decision, 'auto');

    if v_layer = 'content_sha256' then
      -- Byte-identical: there is nothing to keep. The uploader gets a claim
      -- on the SURVIVING file -- PRD §10, contributed counts every upload
      -- that resolved to a track, including one whose bytes were discarded.
      insert into public.file_claims (file_id, user_id, batch_id)
      select v_win_file, f.uploaded_by, f.batch_id
        from public.files f where f.id = p_file_id
      on conflict (file_id, user_id) do nothing;
      select f.r2_key into v_reclaim from public.files f where f.id = p_file_id;
      perform public.ingest_set_state(
        p_file_id, array['stored','received','analysing'], 'rejected_redundant');
      v_action := 'merged_redundant';
    else
      -- KEEP-IF-BETTER. PRD §3 and §7.2. Never overwrite the incumbent:
      -- store the newcomer alongside and flip a pointer, because files are
      -- cheap and re-acquiring a rare promo is not.
      select public.forensics_json(t.preferred_file_id) into v_inc_f
        from public.tracks t where t.id = v_win_trk;
      select public.forensics_json(p_file_id) into v_probe_f;
      if public.dedup_is_upgrade(v_inc_f, v_probe_f) then
        update public.tracks t set preferred_file_id = p_file_id where t.id = v_win_trk;
        v_action := 'merged_upgraded';
      elsif public.dedup_dominated(v_inc_f, v_probe_f) then
        select f.r2_key into v_reclaim from public.files f where f.id = p_file_id;
        perform public.ingest_set_state(
          p_file_id, array['stored','received','analysing'], 'rejected_redundant');
        v_action := 'merged_redundant';
      else
        -- Different container, different bandwidth, or no forensics on
        -- either side. Both files stay. An alternate format is not waste --
        -- a DJ wants the FLAC at home and the 320 on the USB stick.
        v_action := 'merged_alternate';
      end if;
    end if;

    -- Record the reclaim on the merge event, so undo_merge() knows which
    -- rows to bring back to 'stored'. merge_tracks() cannot know this: the
    -- keep-if-better decision happens after it returns.
    if v_reclaim is not null then
      update public.track_merges m
         set reclaimed_file_ids = array[p_file_id]
       where m.id = v_merge_id;
    end if;

  else
    -- No winner: the probe is its own identity. This is the commonest path
    -- and it must be the simplest. Same reuse rule as above, for the same
    -- at-least-once reason.
    select public.canonical_track_id(f.track_id) into v_new_trk
      from public.files f where f.id = p_file_id;
    if v_new_trk is null then
      insert into public.tracks (preferred_file_id) values (p_file_id)
        returning id into v_new_trk;
      update public.files f set track_id = v_new_trk where f.id = p_file_id;
    end if;
    v_win_trk := v_new_trk;
    if v_score >= coalesce(v_cfg.t_related, 0.40)
       and (v_best ->> 'candidateTrackId') is not null then
      -- 0.40-0.70: a related version. Recorded both ways so either track's
      -- page can show it.
      insert into public.track_relations (track_id, related_id, relation, score)
      values (v_new_trk,
              public.canonical_track_id((v_best ->> 'candidateTrackId')::uuid),
              'version', v_score)
      on conflict do nothing;
      insert into public.track_relations (track_id, related_id, relation, score)
      values (public.canonical_track_id((v_best ->> 'candidateTrackId')::uuid),
              v_new_trk, 'version', v_score)
      on conflict do nothing;
    end if;
    v_action := case
      when v_score >= coalesce(v_cfg.t_probable, 0.70) then 'new_track_review'
      when v_score >= coalesce(v_cfg.t_related, 0.40)  then 'new_track_related'
      else 'new_track' end;
  end if;

  if v_decision is not null then
    update public.match_decisions d set action = v_action where d.id = v_decision;
  end if;
  return query select v_action, v_win_trk, v_reclaim;
end $$;
```

```sql
-- ------------------------------------------------------------
-- merge_tracks -- the human path, and the recorder for the automatic one.
--
-- Writes the track_merges row FIRST, capturing everything needed to undo,
-- and only then moves anything. Reconstructing the undo payload later from
-- the current shape of the data is impossible: after the merge there is
-- nothing left that says which files moved.
-- ------------------------------------------------------------
create or replace function public.merge_tracks(
  p_loser uuid, p_winner uuid, p_decision_id bigint default null,
  p_performed_by text default 'auto'
) returns bigint
language plpgsql security definer set search_path = '' as $$
declare
  v_loser  uuid := public.canonical_track_id(p_loser);
  v_winner uuid := public.canonical_track_id(p_winner);
  v_files  uuid[];
  v_prior  jsonb;
  v_id     bigint;
begin
  if v_loser is null or v_winner is null or v_loser = v_winner then
    raise exception 'merge_tracks: nothing to merge' using errcode = 'P0001';
  end if;

  select coalesce(array_agg(f.id), '{}'),
         coalesce(jsonb_object_agg(f.id::text, f.track_id::text), '{}'::jsonb)
    into v_files, v_prior
    from public.files f where f.track_id = v_loser;

  insert into public.track_merges
    (loser_track_id, winner_track_id, decision_id, performed_by,
     moved_file_ids, prior_track_id_by_file, prior_preferred_file_id)
  select v_loser, v_winner, p_decision_id, p_performed_by,
         v_files, v_prior, t.preferred_file_id
    from public.tracks t where t.id = v_winner
  returning id into v_id;

  update public.files  f set track_id = v_winner where f.track_id = v_loser;
  update public.tracks t set merged_into_track_id = v_winner, merged_at = now()
   where t.id = v_loser;
  return v_id;
end $$;
revoke execute on function public.merge_tracks(uuid, uuid, bigint, text)
  from public, anon, authenticated;

-- ------------------------------------------------------------
-- undo_merge -- PRD §6's whole reason the 0.90 band is tolerable.
--
-- "Wrong auto-merges destroy someone's crates" is the first risk in PRD
-- §15, and its mitigation is this function plus the rule that crates read
-- through canonical_track_id() and are never rewritten.
--
-- REFUSES when a later, un-undone merge sits on top of either side. Undoing
-- out of order does not error later -- it silently produces a chain nobody
-- intended -- so the refusal has to be here.
--
-- What it does NOT restore: bytes. A reclaimed object was deleted from R2
-- and no database row can bring it back. The FILE ROW returns to 'stored'
-- and the nightly reconcile then reports it as missing, which is the
-- honest outcome and is why dedup_dominated() is strict about what it will
-- reclaim in the first place.
--
-- Claims are also never rolled back. The upload really did happen, and PRD
-- §10 says contributed never decreases.
-- ------------------------------------------------------------
create or replace function public.undo_merge(p_merge_id bigint)
returns bigint
language plpgsql security definer set search_path = '' as $$
declare m public.track_merges%rowtype;
begin
  -- Owner only, and NOT granted to service_role: an undo is a human
  -- reversing a machine, so there is no automated caller to serve. A
  -- service_role connection has no auth.uid() and would fail this check
  -- anyway; withholding the grant makes that explicit rather than
  -- accidental.
  if not (select public.is_owner()) then
    raise exception 'forbidden' using errcode = '42501';
  end if;

  select * into m from public.track_merges where id = p_merge_id;
  if m.id is null then
    raise exception 'no such merge %', p_merge_id using errcode = 'P0002';
  end if;
  if m.undone_at is not null then
    raise exception 'merge already undone' using errcode = 'P0001';
  end if;
  if exists (
    select 1 from public.track_merges l
     where l.undone_at is null and l.id > m.id
       and (l.loser_track_id  in (m.loser_track_id, m.winner_track_id)
         or l.winner_track_id in (m.loser_track_id, m.winner_track_id))
  ) then
    raise exception 'a later merge depends on this one' using errcode = 'P0001';
  end if;

  update public.tracks t
     set merged_into_track_id = null, merged_at = null
   where t.id = m.loser_track_id;

  -- Every file goes back to the track the payload says it came from, not
  -- to the loser wholesale: a file may have been re-pointed by a later
  -- action, and this is a merge undo, not a restore-from-backup.
  update public.files f
     set track_id = (m.prior_track_id_by_file ->> f.id::text)::uuid
   where f.id = any (m.moved_file_ids)
     and m.prior_track_id_by_file ? f.id::text;

  update public.tracks t set preferred_file_id = m.prior_preferred_file_id
   where t.id = m.winner_track_id and m.prior_preferred_file_id is not null;

  -- Reclaimed rows return to 'stored'. The bytes may be gone; the row is
  -- what a person can act on.
  update public.files f
     set state = 'stored', state_changed_at = now()
   where f.id = any (m.reclaimed_file_ids) and f.state = 'rejected_redundant';

  update public.track_merges
     set undone_at = now(), undone_by = auth.uid()
   where id = m.id;
  return m.id;
end $$;
revoke execute on function public.undo_merge(bigint) from public, anon, service_role;
grant  execute on function public.undo_merge(bigint) to authenticated;
```

`undo_merge` is granted to `authenticated` and gates on `is_owner()` in its body — the same shape as M1's admin RPCs. A member can *see* the merges feed; only the owner can pull a lever on it.

`recent_merges(int)` is the feed's one query: merge id, both sides' display strings, who and when, and whether it is undone. It exists because PRD §6's last "where dedup will fail" bullet is blunt about it: *"Nothing currently surfaces a completed auto-merge for after-the-fact review. Wrong merges are cheap to undo only if someone notices."*

### Task 8: Calibration, and the live acceptance run

Two things: replace the guessed numbers with measured ones, and prove the whole thing works on the pair sitting in production right now.

**The blocking unknowns this task exists to close** — both carried in `plans/README.md` since M1:

| Unknown | Acceptance criterion |
|---|---|
| **GIN `query_items` mask width** — guessed at 12. Too small and transcodes share nothing; too large and everything matches. | `median(\|items_a ∩ items_b\|) / \|items_a\| ≥ 0.35` across 200 files transcoded to 128 kbps. |
| **Dedup thresholds** — 0.90 / 0.70 / 0.40 are AcoustID's constants adjusted by judgement. | The true-pair and random-pair score distributions must be measured, and the three thresholds set where they actually separate. |

**Files:**
- Create: `worker/calibration/transcode_corpus.py`, `calibrate_mask.py`, `score_distributions.py`, `README.md`

**Two constraints on the corpus, both non-negotiable:**

1. **It is not the pool.** The pool holds a handful of files. 200 deliberate transcodes need 200 source files, and the owner's own library is the only place they exist. The corpus is local, listed in `.gitignore`, and **no audio ever enters the repo** — PRD §7.3 rule 6 is explicit that a stray audio file is the likelier embarrassment than a stray API key, and this is the first task that would put one there.
2. **It runs against chromaprint 1.6.0, the container's pinned build.** `algo_version` is the recompute key, and M3 Task 8 caught Debian shipping 1.5.1 while dev had 1.6.0 — two incompatible keys for identical audio. Thresholds measured on 1.5.1 are not transferable. The harness asserts `fpcalc -version` before it does anything, and the honest way to guarantee it is to run inside the built image:

```bash
docker run --rm -v "$PWD/corpus:/corpus:ro" -v "$PWD/out:/out" \
  --entrypoint python localchune-analysis:latest \
  /app/calibration/calibrate_mask.py /corpus /out
```

Under QEMU on the M1 this is slow and its **timings are meaningless** — but the fingerprint values are exact, and values are all this task needs.

- [ ] **Step 1: Build the corpus**

```bash

  --src ~/Music/library --n 200 --out ./corpus
```

200 source files, each paired with a real `ffmpeg -c:a libmp3lame -b:a 128k` transcode of itself. 128 kbps because that is the worst case a real pool contains — if the mask survives 128, it survives 320. The script also emits a `pairs.json` naming which file is a transcode of which.

Add `/corpus/` and `/out/` to `.gitignore` **in the same commit that adds the script**, and make the script **refuse to run** when `--out` resolves inside the repository. Both guards, not one: PRD §7.3 rule 6 says the likelier embarrassment before a public push is a stray audio file, not a stray API key, and this is the first task in the project that would produce two hundred of them.

- [ ] **Step 2: Sweep the mask**

```bash
python worker/calibration/calibrate_mask.py ./corpus --masks 10,11,12,13,14
```

For every mask, for every pair: compute `query_items` both sides and report `|a ∩ b| / |a|`. Output is a table of median, p10 and p90 per mask, plus the median candidate-set size the same mask would produce across the whole corpus.

**The choice rule, decided now so the number is not argued about later:** take the **smallest** mask whose median ratio clears 0.35. A smaller mask keeps more bits, which makes items more specific, which makes the candidate set smaller — and the candidate set is what the offset sweep pays for. Recall is the constraint; specificity is the thing being maximised inside it.

Two ways this ends badly, and what to do:

- **No mask clears 0.35.** The two windows are the problem, not the mask. `(10,40)` and `(60,90)` seconds is a guess, and PRD §6 names the failure directly: *"If the 10–40 s window lands in a differing intro, recall collapses for exactly the pairs you most want to catch."* Sweep window placement before touching the mask further, and remember `algo_version` does not change when the windows do — so **the windows must be folded into `algo_version` if they ever change**, or old and new fingerprints become silently incomparable. Record whichever way it goes.
- **Every mask clears 0.35 easily.** Then the corpus is too easy — probably all one genre, or all from one encoder. Widen it before believing the number.

- [ ] **Step 3: Measure the score distributions**

```bash
python worker/calibration/score_distributions.py ./corpus --out ./out/scores.json
```

Every true pair scored against itself, and 5,000 random non-pairs scored against each other, through the *same* offset sweep the production scorer runs. Emit both histograms and the separation point.

Set the three thresholds from the result:

- `t_same` — the score below which **no** true pair fell, minus a small margin. This is the auto-merge band and a false positive here is a wrong merge. PRD §6 tolerates that only because merges are reversible; do not spend the tolerance for nothing.
- `t_related` — the score above which **no** random pair rose. Anything above this is at least worth logging.
- `t_probable` — between them. The width of that gap is the review-queue size, and PRD §6 warns to expect *"a review queue in the high hundreds"* on the first few thousand files.

Then write them where the system reads them:

```sql
update public.dedup_config
   set t_same = :measured_same, t_probable = :measured_probable,
       t_related = :measured_related, gin_mask = :measured_mask,
       source = 'calibrated 2026-07-XX, 200 pairs @128kbps, fpcalc 1.6.0, corpus N=…',
       updated_at = now()
 where algo_version = 'cp-1.6.0/test2/11025';
```

**If `gin_mask` changed, `make_query_items`' default in `worker/app/fingerprint.py` changes with it, and every existing fingerprint's `query_items` is stale.** That is a re-analysis of the whole pool via `analysis_requeue()` — at four to six files, minutes; at two thousand, the cost model in PRD §10 applies. Do it while the pool is small. This is the single strongest argument for calibrating now rather than at the PRD's nominal 2k tracks.

## Deferred, on purpose

- **Bulk "apply this answer to the other 12 that look like this".** PRD §6 predicts wanting it *"sooner than expected"* and PRD §15 lists it as a risk mitigation. It is genuinely useful only once the queue is in the high hundreds, and its natural shape — cluster the pending decisions by candidate track and resolve a cluster — cannot be designed against a queue of one. Revisit at the first backfill.
- **Panako 2.0 for vinyl rips at a different playback speed.** PRD §6 is unambiguous: chromaprint is not robust to tempo shift, a rip mastered 0.5 % fast scores below 0.40 forever, and Panako is a JVM application and a whole second matcher. Out of scope for v1, duplicates accepted. `dedup_near_misses` exists so the trigger — near-misses clustering with a 1–3 % duration delta — is one query away.
- **`tracks`' canonical-metadata columns.** M7's, in M7's migration.
- **A dedicated `analysis_worker` Postgres role** (M3 review finding F2, still open). M4 adds four service_role functions to a surface that already has four; the role split is one change across all of them, and doing it inside this milestone would mix an authz refactor into a dedup review.
- **Widening `reconcile.ts`'s `STATES_SAFE_TO_AUTO_DELETE`.** `rejected_redundant` is now a third meaning for "the row outlived its object", alongside `failed` (good bytes, failed analysis) and `abandoned` (never completed). `RECONCILE_DELETE_PENDING` stays `"false"` until that job can tell all three apart.
- **`ingest_mark_missing(uuid)`** — M2 asked M3 for it, M3 did not add it, and M4 does not need it. Still open, still better than an uncalled function.
- **The ONNX switch** (10–20 % less CPU and a smaller image, inverted on amd64 at M3 Task 8). Task 1 already changes the container; changing the beat runtime in the same deploy would make a `cpu_seconds` regression unattributable.
